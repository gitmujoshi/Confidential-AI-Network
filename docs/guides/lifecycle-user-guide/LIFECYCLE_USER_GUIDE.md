This guide walks through the full multi-party happy path in the local stack:

1. **Enterprise-register** **TDC**, **TDP**, and **TSP/CCRP** (User Type = Enterprise + organization)
2. TDP publishes an NLP dataset (Hugging Face `ag_news` reference)
3. TDC creates a Ricardian contract with **PyTorch** / **Tiny DistilBERT** and **differential privacy (DP-SGD)**
4. TDP and TSP are notified, review, and sign
5. TDC views the **SIGNED** contract, runs local-docker training, and inspects **logs** + **provenance**

## Happy path

### 1. Enterprise onboard TDC

Open **User Registration** and set **User Type** to **Enterprise**.
Choose role **TDC (Training Data Consumer)**, enter the organization name, public key, and register.

![Enterprise onboard TDC](screenshots/01-onboard-tdc-register.png)

### 2. TDC first login dashboard

After first-login password setup, the enterprise TDC lands on their dashboard and can browse datasets / create contracts.

![TDC first login dashboard](screenshots/02-onboard-tdc-dashboard.png)

### 3. Enterprise onboard TDP

Register an enterprise **TDP (Training Data Provider)** with organization details.
This party publishes datasets and signs contracts that use them.

![Enterprise onboard TDP](screenshots/03-onboard-tdp-register.png)

### 4. TDP first login dashboard

The TDP dashboard is the home for datasets and incoming signature requests.

![TDP first login dashboard](screenshots/04-onboard-tdp-dashboard.png)

### 5. TDP publishes an NLP dataset

The TDP publishes a **text / NLP** catalog dataset backed by the well-known Hugging Face **`ag_news`** reference.
TDCs select this dataset when creating a privacy-preserving training contract.

![TDP publishes an NLP dataset](screenshots/05-tdp-dataset-published.png)

### 6. Enterprise onboard TSP / CCRP

Register an enterprise **TSP** (Tech Service Provider; also called CCRP in older docs).
This party hosts the training environment and co-signs the contract.

![Enterprise onboard TSP / CCRP](screenshots/06-onboard-tsp-register.png)

### 7. TSP Local cloud readiness

Configure the enterprise TSP with a **Local** provider so contracts can run with `TRAINING_EXECUTION_MODE=local-docker` in this environment.

![TSP Local cloud readiness](screenshots/07-onboard-tsp-local.png)

### 8. TDC creates contract — NLP model & dataset

The TDC selects the TDP **AG News** NLP dataset and the catalog model **Tiny DistilBERT (NLP DP)**.
Contract terms reference **PyTorch** training with **differential privacy (DP-SGD)**.

![TDC creates contract — NLP model & dataset](screenshots/08-tdc-create-details.png)

### 9. TDC creates contract — select TSP

Select the onboarded **TSP** (Local) and environment/KMS settings for the training session.

![TDC creates contract — select TSP](screenshots/09-tdc-create-tsp.png)

### 10. TDC creates contract — submit path

Complete environment/KMS settings and submit the wizard.
The contract enters **PENDING_TDP_APPROVAL** and notifies the TDP (then TSP after TDP signs).

![TDC creates contract — submit path](screenshots/10-tdc-create-submit.png)

### 11. TDP gets notified

The TDP sees signature / contract notifications for agreements that reference their datasets.

![TDP gets notified](screenshots/11-tdp-notifications.png)

### 12. TDP reviews and signs

On **Contract Details**, the TDP reviews terms and clicks **Sign Contract as TDP**. Status advances to **PENDING_TSP_APPROVAL**.

![TDP reviews and signs](screenshots/12-tdp-sign.png)

### 13. TSP / CCRP gets notified

The TSP is notified when a contract is waiting for clean-room provider signature.

![TSP / CCRP gets notified](screenshots/13-tsp-notifications.png)

### 14. TSP / CCRP reviews and signs

The TSP reviews environment commitments and signs. When TDP and TSP have both signed, status becomes **SIGNED**.

![TSP / CCRP reviews and signs](screenshots/14-tsp-sign.png)

### 15. TDC views the signed contract

The TDC opens the contract and confirms **SIGNED** (TDP + TSP signatures complete).

![TDC views the signed contract](screenshots/15-tdc-signed-contract.png)

### 16. TDC starts training

On **Training**, the TDC starts a job for the signed contract (`TRAINING_EXECUTION_MODE=local-docker` in local env).

![TDC starts training](screenshots/16-tdc-training-ready.png)

### 17. Training completed (PyTorch + DP-SGD)

When the local trainer finishes, the job status is **COMPLETED**.
For this tour the run uses **PyTorch** / **Tiny DistilBERT** with **differential privacy (DP-SGD)** metrics when available.

![Training completed (PyTorch + DP-SGD)](screenshots/17-tdc-training-completed.png)

### 18. TDC views provenance report

**View job provenance** opens the host/API provenance bundle (datasets, model architecture, privacy metrics, artifacts).

![TDC views provenance report](screenshots/18-tdc-provenance.png)

### 19. TDC views training run logs

**View logs** shows trainer/runner output (framework, architecture, DP flags) captured for the local-docker job.

![TDC views training run logs](screenshots/19-tdc-training-logs.png)
