As a Tech Service Provider (also called CCRP in older docs) you host confidential training on a Local machine or on your existing Azure or GCP cluster. Save the cluster and kubeconfig path on the dashboard **Cloud Provider** card, and **co-sign** contracts with the party signing key from registration.

## Happy path

### 1. Sign in

1. Open the app and go to **Login**.
2. Enter your email and password.
3. Click **Sign In**. On first login you may be asked to set a new password.

![Sign in](screenshots/tsp/01-login.png)

### 2. Dashboard

The **TSP dashboard** shows environment health, contracts that need your signature, and the **Cloud Provider** card.
Edit that card to choose Local, Azure, or GCP. Azure asks for Subscription ID, Resource group, AKS cluster name, Namespace, Region, Storage account, Key Vault URI, and Kubeconfig path. GCP asks for Project ID, Location, GKE cluster name, Namespace, GCS bucket, and Kubeconfig path.
Training uses this existing cluster. The kubeconfig path is a file on this host.

![Dashboard](screenshots/tsp/02-dashboard.png)

### 3. Contracts

Confirm clean-room requirements (TEE / residency / policies), then **Sign** when you can host the job.
Signing uses the **party signing key** created at registration (same ECDSA-P256 / RSA choice as TDP/TDC).

![Contracts](screenshots/tsp/03-contracts.png)

### 4. Cloud credentials

**Cloud credentials** stores provider login material used when creating environments. The cluster name and kubeconfig path used by Azure and GCP training are saved on the dashboard **Cloud Provider** card.

![Cloud credentials](screenshots/tsp/04-cloud-credentials.png)

### 5. Infrastructure

**Infrastructure** / provisioning views cover capacity and environment setup for training runs.

![Infrastructure](screenshots/tsp/05-infrastructure.png)

### 6. Training environment

Monitor or configure the **training environment** used for local Docker or cloud CCR sessions.

![Training environment](screenshots/tsp/06-training-environment.png)

### 7. Notifications

Signature requests and provisioning alerts appear under **Notifications**.

![Notifications](screenshots/tsp/07-notifications.png)
