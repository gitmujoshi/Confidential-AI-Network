Deployment

Start with the deployment hub. It lists every common setting, which file it belongs in, and the extra inputs for local, Azure, Google Cloud, AWS, and OCI.

Local development is ./start-system.sh. Cloud jobs use a cluster the provider already runs. The kubeconfig path is stored on the provider card. A missing path fails the job.

Where a job runs

  • Azure submits to the existing AKS cluster named on the contract and the provider card.
  • Google Cloud uses the existing GKE cluster and project.
  • Oracle uses the existing OKE runner.
  • AWS training is not implemented. The API returns 501.

Azure platform

Terraform can create the AKS cluster, PostgreSQL, the container registry, a platform Key Vault, and Blob storage. These stay off until the matching setting is turned on:

  • Confidential node pool. The training job reads a SEV-SNP report from the node. The job stays simulated until that report verifies. A node without the guest interface fails the job.
  • API Management and its Entra token check. It is created only when the publisher email and the API address are set.
  • External Secrets. Terraform creates the identity. The operator install is a separate script and stops when the vault or the cluster is missing.
  • SCITT on AKS. The install script deploys this product's ledger. It stops when the image or database URL is missing.

Signing stays in the database until SIGNING_KEY_BACKEND is azure-keyvault. Dataset and model key release stays on recorded release times until CAN_PRINCIPAL_KEY_MODE is azure-skr.

Still an operator step

  • Apply Terraform to a subscription, then point DNS at the load balancer.
  • Install SPIRE with Helm after its namespace scaffold.
  • Run the training job on a confidential node when a real SEV-SNP report is required.

The module list, flags, and install scripts are in deployment/azure/terraform/README.md. Readiness and the setting catalog are in docs/deployment.
